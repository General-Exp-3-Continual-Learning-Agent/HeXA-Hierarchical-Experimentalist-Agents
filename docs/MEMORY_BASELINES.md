# Memory baselines: Episodic RAG and MemRL

Two cross-episode memory baselines for InterPhyre, in `baselines/`. They exist to
separate *"HeXA works because it distils skills"* from *"HeXA works because it has
any memory at all"* — the three baselines in [BASELINES.md](BASELINES.md) either
have no memory (ReAct, Direct) or memory confined to a single seed (Reflexion).

Both are lifelong learners over the same 50-seed grid HeXA uses, and both inject
into the same seam HeXA's skill bank uses, so the only thing that differs between
methods is the injected block.

| | Stored | Retrieval | Update | Bank size |
|---|---|---|---|---|
| Episodic RAG | raw rollouts, last 12 steps | nearest success + nearest failure | append only | unbounded |
| MemRL | LLM-summarized experiences | top-k1 by cosine, then top-k2 by similarity+utility | Monte-Carlo Q update per episode | unbounded, near-duplicates merged |
| HeXA | distilled skills + mistakes | top-K by confidence | teacher evolves the bank per round | capped at 10 |

## Provenance

**Episodic RAG** follows the CORE paper (arXiv 2605.28742, §4.1): all rollouts go
into a memory indexed by problem embedding; each inference gets the most similar
past *successful* rollout and the most similar past *unsuccessful* rollout with
their verifier feedback; if either class is empty, retrieve by similarity alone.
No summarization, no utility.

**MemRL** is ported from the official release (MemTensor/MemRL, arXiv
2601.03192) using its **ALFWorld** configuration — of its four benchmarks, the
closest analogue to InterPhyre. Memory holds Intent-Experience-Utility triplets:

- **Phase A** — candidates `= TopK_k1({i : cos(z_q, z_i) > δ})`; empty ⇒ inject
  nothing and let the frozen model explore.
- **Phase B** — pick top-`k2` by `(1−λ)·ẑ(sim) + λ·ẑ(Q)`. Similarity is z-scored
  against **precomputed dataset statistics**; Q is z-scored against the
  **candidate pool**, clipped to ±3.
- **Update** — `Q ← (1−α)Q + α(r + γ·maxQ')` with `γ = 0` (Monte-Carlo), applied
  to every memory that was injected. `r = +1` success, `−1` failure.
- **Write-back** — success ⇒ `SCRIPT + TRAJECTORY` (proceduralization); failure ⇒
  a reflection note (adjustment). Only the *intent* is embedded, not the content.

Defaults: `k1=5, k2=3, λ=0.5, α=0.3, Q_init=0`, reward attribution to merge
targets at 0.85 with gain 0.1. Near-duplicate merge is **0.99**, not their
ALFWorld 0.90 — see the known limitation below.

Both methods store the **last 12 steps** of a trajectory, each observation capped
head+tail at 600 chars. MemRL's 12 is its own `--max-traj-steps`; Episodic RAG's
is a deviation from the CORE paper (which stores rollouts verbatim), adopted
because an untruncated block OOMs gpt-oss-120b under eager attention, and because
holding trajectory length equal isolates the axis under test — summarized vs raw
memory — from sheer context volume. Note this weakens the paper's
context-efficiency comparison; `--max-traj-steps 0` restores verbatim storage for
a run where context is not the binding constraint.

## Reproducing the experiments

Prerequisites: the conda env and `PYTHONPATH` from the repo root (see
`INSTALL.md`); `OPENAI_API_KEY` available for MemRL's embedder — put it in
`~/.config/interphyre/openai.env` as `export OPENAI_API_KEY=...` (mode 600) and
`baselines/bash_scripts/_baseline_env.sh` will source it. No key is needed for
Episodic RAG.

Everything below writes to `baselines/data/results/<method>_<level>_<actor>/`
and reads shared caches from `baselines/data/cache/`.

### Actors

| label | model | launcher | resources |
|---|---|---|---|
| `qwen7b` | Qwen2.5-7B-Instruct | `sbatch_baseline_qwen.sh` | 1 GPU, 64G |
| `qwen3b` | Qwen2.5-3B-Instruct | `sbatch_baseline_qwen.sh --actor-label qwen3b` | 1 GPU, 64G |
| `gptoss120b` | gpt-oss-120b | `sbatch_baseline_oss.sh` | 4x A100 80GB, 480G |
| `claude` | Claude Sonnet via `claude -p` | `sbatch_baseline_claude.sh` | cpu partition |

Model paths for this cluster are recorded in `_baseline_env.sh` as `QWEN_PATH`,
`QWEN3_PATH`, `GPT_OSS_PATH`; override any of them by exporting before `sbatch`.

### Step 0 — starter trajectories (only if the level has none)

`Initial_trajectories/<level>/` must exist. `catapult` ships 5 (Claude-generated,
with the repo); `down_to_earth` and `two_body_problem` have 8 each, generated by
plain ReAct with Qwen-7B. To add a level:

```bash
sbatch baselines/bash_scripts/sbatch_seed_trajectories.sh \
    --level <level> --seeds "1 2 3 4 5 6 7 8"
```

This doubles as a capability probe: if the actor scores 0/8, both baselines will
floor at 0% and the runs are not worth doing.

### Step 1 — calibrate (MemRL only)

MemRL reads `delta`, `sim_norm_mean`, `sim_norm_std` from a calibration file and
refuses to start without one matching its `(level, intent mode, key)`. Episodic
RAG needs no calibration.

```bash
python -m baselines.calibrate --level <level> --seeds 1-105 \
    --intent-mode geometry --embedding-model openai:text-embedding-3-large \
    --cache-dir baselines/data/cache
```

Seconds to a minute per level. Read the printed Spearman rho and top-k overlap
before trusting a run — see the retrieval-key section below.

### Step 2 — run

Seeds must not overlap the starter set: `catapult` uses `6-55`, the other two
`9-58`.

```bash
# the full 14-run matrix used for the reported results
for ACTOR in qwen7b qwen3b; do
  for LEVEL in down_to_earth two_body_problem catapult; do
    SEEDS=$([ "$LEVEL" = catapult ] && echo 6-55 || echo 9-58)
    for METHOD in episodic_rag memrl; do
      sbatch baselines/bash_scripts/sbatch_baseline_qwen.sh \
        --method $METHOD --level $LEVEL --seeds $SEEDS \
        --initial-traj-dir Initial_trajectories/$LEVEL --actor-label $ACTOR
    done
  done
done
# 3B needs its own weights:  --export=ALL,QWEN_PATH=$QWEN3_PATH

for METHOD in episodic_rag memrl; do
  sbatch baselines/bash_scripts/sbatch_baseline_oss.sh \
    --method $METHOD --level catapult --seeds 6-55 \
    --initial-traj-dir Initial_trajectories/catapult
done
```

Do **not** pass `--embedding-model`: each runner applies its own default (see the
standing convention below). Runs resume — resubmitting skips seeds whose
trajectory JSON already exists.

### Step 3 — read the results

```bash
python -m baselines.analysis.compare_runs baselines/data/results/*_down_to_earth_*
python -m baselines.analysis.show_episode baselines/data/results/memrl_down_to_earth_qwen7b 9
```

Every run writes `manifest.json` with the complete resolved configuration —
all 22 MemRL hyperparameters, the actor, the embedder, the calibration file it
read, the seed spec, and an explicit deviations list. A run is reproducible from
its manifest alone.

### Verify a run actually exercised the method

Two failure modes are silent, both found the hard way. Check them before
believing a number:

| check | command | healthy |
|---|---|---|
| memory bank grew | `jq .num_records <run>/memory_store.json` | ~one record per episode, not 2 |
| success memories have recipes | `grep -c 'SCRIPT:\\n\\n\\nTRAJ' <run>/memory_store.json` | 0 |
| memory was actually injected | `compare_runs` -> `episodes w/ none` | not most of them |
| no summarizer failures | `grep 'WARNING: summarizer' logs/...` | no hits |

**Known limitation.** `add_similarity_threshold` (merge-on-write) is 0.99 —
their LifelongBench value, not the 0.90 of their ALFWorld config, because on
InterPhyre 99-100% of scene pairs exceed 0.90 and the bank collapses to one
record per outcome class. Even at 0.99, `catapult` under either text embedder has
>1% of pairs above the threshold, so its bank may still collapse; check
`num_records`. `--embedding-model numeric` avoids the problem entirely.

### Step 1 is not optional for MemRL

MemRL's Phase-A threshold δ is dataset-density dependent — the paper sets it to
the top-20% quantile of the benchmark's pairwise task-description similarities,
and its config hardcodes per-benchmark similarity-normalization statistics.
`baselines/calibrate.py` measures all three on InterPhyre intents;
`run_memrl.py` refuses to start on ALFWorld's values, and refuses a calibration
measured with a different embedder or intent mode.

## Which embedder each method uses

**Standing convention: Episodic RAG runs on jina, MemRL on OpenAI
`text-embedding-3-large`** — each method uses the embedder its own source names:

```
Episodic RAG  ->  jinaai/jina-embeddings-v2-base-en   (the CORE paper's choice)
MemRL         ->  openai:text-embedding-3-large       (configs/rl_alf_config.yaml)
```

Both are per-runner defaults, so a standard run passes no `--embedding-model` at
all. `OPENAI_API_KEY` is read from `~/.config/interphyre/openai.env`, outside the
repo. Overriding is for ablations only — putting both methods on one key removes
the embedder confound from a MemRL-vs-RAG comparison, and `numeric` gives the
best-conditioned retrieval space.

Note the trade-off this creates: it is faithful to each paper, but a MemRL-vs-RAG
gap then mixes "summarized vs raw memory" with "which embedder". Report the
shared-key variant alongside it if that distinction matters.

## The retrieval key: why it is not a text embedding

Both papers embed a *task description*. On InterPhyre that does not work, and the
calibration run is what establishes it. Within one level, every intent is the
same template with different numbers, so language-model embeddings come out
nearly collinear — and, more importantly, their **ranking barely tracks scene
similarity**, which is the only thing retrieval uses:

A compressed range alone would be survivable: δ is a quantile and z-normalization
rescales whatever variance exists. Retrieving at ρ ≈ 0.11 is not — it makes
Phase A draw near-arbitrary memories, which would turn both baselines into straw
men and make any HeXA win meaningless.

A stronger embedder does not rescue the ranking. `text-embedding-3-large` widens
the spread 4-14x (catapult std 0.0005 -> 0.0046, down_to_earth 0.0013 -> 0.0189,
which does fix delta) but leaves rho at +0.17 to +0.34 and top-1 overlap at
6.7-15.2%. On down_to_earth rho actually *fell*, +0.45 -> +0.28. The limit is the
intent representation, not the model reading it: LMs do not rank numeric tuples
by geometric proximity.

**`--embedding-model numeric`** — the standardized geometry vector, cosine-compared
like any other embedding — is therefore the only well-conditioned key we have. It
is not the default, because each paper specifies a text embedder and we run each
method on its own (see above); but it is the right ablation to report alongside,
and the gap between the two is itself a finding.

Note that the choice was made from a diagnostic over **geometry alone** — no
rewards, no evaluation labels, no success rates — so it does not constitute
tuning on the evaluation set.

`baselines/memory/features.py` holds the key, the scaler, and the diagnostic;
`rank_agreement` scores both sides with cosine (the metric retrieval actually
uses) so identical keys score ρ = 1.

## Protocol

Seeds **6–55 in order** (the grid the other baselines used), optionally preloaded
with the level's `Initial_trajectories/` for the same Off2On head start HeXA
gets. Retrieve → solve (≤25 iterations) → update utilities → write back, once per
seed. Results are grouped into rounds of 3 so the curve overlays HeXA's rounds.

`--freeze-after N` makes memory read-only from stream index N, which is MemRL's
"Transferring" setting (frozen bank, unseen instances).

`--lambda-q 0` is the runtime-RL ablation: Q-blind retrieval, everything else
identical.

## What gets logged

Per episode, in `episodes.jsonl` and each trajectory JSON:

- `success`, `iterations`
- `simulator_calls` — the real rollout budget in an experimentation environment
  (a `simulate_action` call, not a ReAct iteration)
- `added_context_tokens` — CORE's context-efficiency axis; raw-rollout replay
  costs an order of magnitude more prompt than a bounded skill bank, and this
  measures it on our environment
- `retrieval_diagnostics` — which memories were considered, their similarity, Q,
  and composite score; and *why* nothing was injected when nothing was
- `utility_updates` — old Q, new Q, reward, visit count per injected memory

`summary_<method>.json` adds per-round accuracy, the running success rate, and
memory-bank statistics. `manifest.json` records the full config and an explicit
list of deviations from the published setups.

## Deviations, by actor

| | Claude | Qwen 7B / 3B | gpt-oss-120b |
|---|---|---|---|
| MemRL temperatures (0.0 / 0.3) | **not reproducible** — `claude -p` has no temperature flag | honoured | honoured |
| Retrieval key | per-method default (MemRL openai, RAG jina) | same | same |
| Comparable with published HeXA numbers | direct (same actor) | no — needs HeXA/ReAct on the same model | no — same caveat |
| Notes | untested end-to-end; needs the CLI reachable from a compute node | 1 GPU each | 4x A100; eager attention only, so context is memory-bound |

HeXA's `DIAGNOSTIC_ADDENDUM` is deliberately **not** injected into either
baseline: it instructs the agent to cite skills, which is method-specific
scaffolding.
